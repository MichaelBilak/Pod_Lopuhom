# Безопасность (Security)

## Проведённый анализ

### Зависимости
- **npm audit**: уязвимостей не обнаружено (0 vulnerabilities).

### Аутентификация админки
- Вход по логину/паролю из переменных окружения (`ADMIN_LOGIN`, `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`).
- Сравнение паролей в **constant-time** (`constantTimeEqual`) — защита от timing-атак.
- Сессия в виде JWT с подписью HMAC-SHA256, хранится в **httpOnly** cookie.
- **Rate limiting** на логин: не более 5 попыток за 10 минут по IP; при ошибке задержка ~600 ms.
- Middleware проверяет сессию для `/api/admin/*` и `/k7fQ9aP2`; при отсутствии сессии API возвращает 404.

### Загрузка файлов (Supabase Storage)
- Эндпоинт `/api/admin/upload` доступен только авторизованному админу (middleware).
- Загрузка идёт в Supabase Storage, бакет `products` (см. `supabase/storage-setup.sql`).
- Запись в бакет разрешена политикой только для `service_role` —
  публикуемый ключ из браузера не может писать.
- Проверка MIME: разрешены только JPEG, PNG, WebP, GIF.
- Ограничение размера файла: **10 MB** на файл — снижение риска DoS и переполнения.
- Удаление файлов: умеет удалять как из Supabase Storage (новые), так и
  из Cloudinary (старые фото) — определяется по URL.

### API и данные
- Supabase: запросы через клиент с параметризацией — риск SQL-инъекций минимизирован.
- Удаление/изменение товаров и изображений доступно только через защищённые админские маршруты.

### Секреты
- Файлы `.env` и `.env.*` в `.gitignore` — не попадают в репозиторий.
- Используются переменные окружения для Supabase, (опционально) Cloudinary и админ-учётных данных.
- `SUPABASE_SERVICE_ROLE_KEY` хранится только в серверном окружении и **не**
  попадает в браузер (используется только в API-роутах `/api/admin/*`
  под Node-рантаймом).

---

## Рекомендации

1. **Секреты**: в продакшене задавать `ADMIN_SESSION_SECRET`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`, ключи Supabase и Cloudinary только через окружение (Vercel/хостинг), не хранить в коде.
2. **Пароль админа**: использовать надёжный пароль; при необходимости — смена пароля через смену `ADMIN_PASSWORD` и перезапуск.
3. **HTTPS**: в production обязательно использовать HTTPS (cookie с `secure: true` в production).
4. **Мониторинг**: при необходимости добавить логирование неудачных попыток входа и подозрительных запросов.
5. **Обновления**: периодически запускать `npm audit` и обновлять зависимости.
